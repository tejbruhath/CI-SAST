# Tasks

---

## Group A — No Dependencies (Fully Parallel)

**A1. Unified Findings Schema**
Define the internal JSON schema that everything normalizes to. This is the contract the entire system is built on. Do this first, even before scanners.

**A2. Scanner Setup — SAST**
Semgrep, Gitleaks, SonarQube. Each independently installable and runnable. Configure rules, output SARIF.

**A3. Scanner Setup — SCA**
Trivy, OWASP Dependency-Check. Independent of SAST.

**A4. Scanner Setup — DAST**
ZAP or Burp headless. Needs a staging target but independent of static scanners.

**A5. Scanner Setup — IAST**
Agent instrumentation (Contrast or Datadog IAST). Independent of DAST setup.

**A6. Async Fuzzing Infra**
AFL++ / Boofuzz running as a continuous CronJob against staging. Independent of all other scanners.

**A7. RAG Corpus Build**
Ingest codebase, CVE/CWE DB, OWASP rules, internal policies into a vector store. No dependency on pipeline.

**A8. Provenance Store**
Design schema, stand up the store, expose a write API. No pipeline dependency — other components just write to it.

**A9. HITL Interface**
Diff viewer, approve/deny/edit actions. Can be built against mock data. No pipeline dependency.

**A10. ASPM Dashboard Skeleton**
UI shell with mock data. Risk posture, finding list, PR management, audit trail, metrics panels. Wire to real data later.

---

## Group B — Depends on Group A

**B1. SARIF Normalizer per tool** ← A2, A3, A4, A5
One normalizer per scanner. Each converts tool-native output → SARIF → A1 schema.

**B2. Aggregator** ← B1, A1
Merges all SARIF outputs into `unified_findings.json`. Handles deduplication at the raw finding level.

**B3. Cross-pipeline Deduplicator** ← A1
Fingerprint-keyed dedup across CI and CD findings. Feeds ASPM. Depends only on the schema.

**B4. LLM Triage Module** ← A1, A7
Structured classifier: real / FP / noise. Must output citations — file location, rule hit, dependency metadata. Integrates RAG corpus.

**B5. Segregator + Router** ← A1, B4
Scoring on severity × complexity × fixability. Policy engine for model dispatch. Claude / DeepSeek / Rule-based / Manual lanes.

**B6. Fix Generator — Context Assembly** ← A7
AST-aware retriever. Given a finding, pulls the vulnerable file, callers, imports, related models, existing tests. This is the hardest subtask — build and evaluate independently.

**B7. Fix Generator — Patch + Validation Loop** ← B5, B6
Prompt design per finding class. Patch generation. Re-validate against scanner. Retry with circuit breaker (max 3). Escalate to manual on failure.

**B8. PR Automation** ← A9
GitLab MR API. Branch naming (`fix/gitguard-ci-*`, `fix/gitguard-cd-*`). CI skip rule for fix branches. Wires after HITL approval.

---

## Group C — Integration (Depends on Group B)

**C1. Pipeline 1 — CI Wiring** ← A2, A3, B1, B2, B4, B5, B7, A9, B8
Connect: push trigger → SAST + SCA → SARIF → aggregate → triage → segregate → route → fix → HITL → PR. Add recursive trigger guard.

**C2. Pipeline 2 — CD Wiring** ← A4, A5, B1, B2, B4, B5, B7, A9, B8
Connect: staging deploy → DAST + IAST → IAST correlation gate → SARIF → aggregate → triage → route → fix → HITL → PR.

**C3. Provenance Write Hooks** ← A8, B7, A9
Wire provenance writes into: patch generation, validation result, HITL approval state. Every stage writes.

**C4. ASPM Full Integration** ← A10, B3, A8, C3
Replace mock data with live reads from provenance store and deduplicator. Manual queue surfaced here.

---

## Join Point

Once C1 + C2 + C3 + C4 are done, you have the full system. End-to-end integration test across both pipelines.
